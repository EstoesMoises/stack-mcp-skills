# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Framework-free static HTML, CSS, and JavaScript generated by the repository's Python build tooling and hosted on GitHub Pages.

## Users

Developers and technical teams evaluating public Stack Internal Agent Skills in local Codex, Claude Code, or GitHub Copilot CLI projects. Their job is to discover a workflow that adds value beyond the MCP tools, understand its permissions and prerequisites, install it through the client's native marketplace, and verify it safely.

## Product Purpose

Make a deliberately small initial set of non-redundant skills browsable and installable without manual filesystem copying. Success means a new user can install a workflow, connect Stack Internal MCP separately, and observe behavior the MCP tool definition does not provide by itself.

## Positioning

One canonical catalog deterministically produces the public site, one plugin per retained skill, and native marketplace metadata for Codex, Claude Code, and GitHub Copilot CLI. The marketplace complements the MCP: it packages higher-order workflows, not wrappers around individual tools.

## Operating Context

Users browse a public GitHub Pages catalog, then work in a terminal and in Codex, Claude Code, or GitHub Copilot CLI. They may need to distinguish marketplace registration, plugin installation and discovery, and separate Stack Internal MCP/OAuth setup.

## Capabilities and Constraints

- Four initial skills: one core uncertainty guardrail and three extended outcome-specific workflows.
- Individual native plugin installation, with the core selection remaining independently manageable.
- Search and filtering run locally in the browser.
- The site and generated catalog are deterministic from repository content and an explicit source commit.
- No backend, hosted model, MCP proxy, tenant form, analytics, third-party runtime asset, custom installer, or package-manager behavior.
- Codex command-driven marketplace scope is client-managed; Claude Code supports explicit project scope; Copilot CLI installs native plugins while other Copilot surfaces use filesystem skills.
- Compatibility remains experimental until exact-version tenant-backed evidence passes.
- Tool-level security and authorization remain the responsibility of the MCP server.

## Brand Commitments

Use the names “Stack Internal Skills” and `stack-internal`. The voice is direct, technical, factual, and explicit about safety boundaries. Do not fabricate customers, benchmarks, compatibility claims, or proof.

## Evidence on Hand

The canonical catalog, skill frontmatter and instructions, generated manifests, adapter guides, smoke-test contracts, source commit, and initial-release assessment are the only evidence. No customer stories, usage analytics, ratings, or approved marketing imagery exist and none may be invented.

## Product Principles

- Ship only workflows that add judgment or composition beyond MCP tool definitions.
- Preserve local-first uncertainty handling and partial progress.
- Make installation commands and next steps immediately actionable.
- Separate installation, discovery, and MCP authentication states clearly.
- Expose source, version, permissions, and experimental compatibility honestly.
- Keep every public artifact reproducible, inspectable, and free of tenant-specific data.

## Accessibility & Inclusion

The catalog must remain usable with keyboard navigation, visible focus, semantic headings and labels, sufficient contrast, reduced motion, narrow screens, and JavaScript disabled for core browsing and installation instructions.
