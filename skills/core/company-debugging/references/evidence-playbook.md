# Evidence playbook

Load this reference when internal sources compete, conflict, or leave uncertainty about diagnosis strength.

## Rank source strength

Rank sources in this order:

1. **Direct relevance:** Prefer full content that names the same component, failure mode, environment, and conditions.
2. **Accepted status:** Prefer an accepted answer when it directly addresses the observed issue.
3. **Support:** Consider score and comments as corroboration. Attribute comments and do not let a score outweigh a direct mismatch.
4. **Recency:** Prefer newer guidance only when dates are available and relevance is otherwise comparable.

Search results, titles, tags, and snippets only select sources; they do not establish a practice. Retrieve the complete question or article first. Retrieve comments for relevant Q&A and distinguish a commenter's context from accepted guidance.

## Resolve conflicts

State each conflicting source with title and ID. Explain why one appears stronger using the ordered criteria above, or keep the result `partial-internal-match` when the conflict cannot be resolved. Never merge contradictory instructions into an invented company rule.

## Match diagnosis to evidence

Use `established-company-practice` only when direct full content and observed conditions agree. Use `partial-internal-match` when a source is useful but materially different. Use `new-hypothesis` when evidence is absent, incomplete, inaccessible, or contradicted without a stronger applicable source; disclose the gap and test the hypothesis against code and runtime facts.
